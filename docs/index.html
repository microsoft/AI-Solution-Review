What it is

Four things, in order, with evidence at the end of each one.

You get a scored baseline, risk-ranked findings with concrete remediation steps, and — once you have made the fixes — a re-run measured against that baseline.

  • 01

    Review

    Configuration, orchestration, knowledge and data grounding, and traces, checked against best practice.

  • 02

    Debug

    Failure modes surfaced from your own transcripts and telemetry, not guesswork.

  • 03

    Optimize

    Gaps named and ranked — including evals generated for you where you have none.

  • 04

    Validate

    Fix, then prove the fix worked against your baseline.

The loop

A review is not a one-off report. It closes.

The tool stays in your environment afterward, so you can review your agents again whenever you want.

What it checks

Four areas, checked against field practice.

  • Configuration

    How the agent is set up: instructions, skills, tools, manifests, and the settings that shape its behavior.

  • Orchestration

    How work is routed between agents, topics, and tools. Overlapping delegation triggers and contradictory guidance between parent and child agents are common and expensive.

  • Knowledge and data grounding

    What the agent is grounded in, and whether its answers are actually supported by it.

  • Traces

    Real runtime behavior from your own transcripts and telemetry: where conversations fail, what the agent actually did, and where users give up.

Checks are grounded in field practice — each one tests the agent against best practices Microsoft teams gathered across customer engagements. Findings cite their sources, including Microsoft Learn and published references such as OWASP.

What you get

Four things you can take to a stakeholder.

  • Confidence

    You know whether the agent is ready to ship.

  • Diagnosis

    Named failure modes instead of guesses about what is wrong.

  • Priority

    A risk-ranked backlog, so the highest-impact fixes come first.

  • Evidence

    A before-and-after score you can hand to stakeholders.

The Agent Review Center

The tool behind the review.

It runs in your own environment, against your own agents.

  • Scored review result

    A rolled score across every agent reviewed — a grade and a number, such as B+ · 87/100 — with per-agent tabs so you can see which agent is dragging the score.

  • Review summary

    Total checks passed, broken down into passed, needs attention, and fail, plus the count of references cited.

  • Findings list

    Every finding, expandable, filterable by component and status, showing parsed fact, impact, recommendation, and detection method. You can include or ignore a rule, or jump straight to editing the skill.

  • Agent map

    How your agents connect, so routing and delegation problems are visible as structure, not buried in instructions.

  • Runtime analysis

    Behavior from real runs, not just static configuration.

  • Conversation analytics

    Coverage across your agents, conversations analyzed, detected risks, PII exposure, sentiment breakdown, and activity trends over time.

  • Agent debugger

    Step through a failed conversation and see variable values and the steps the agent actually took.

  • Rule packs

    Versioned sets of checks, so you know exactly which rules produced a result and can compare like with like.

  • Snapshots and re-run

    Keep a snapshot of a review and run it again later. This is what turns “we changed some things” into a measured before-and-after.

  • Share results

    Hand the scored result to your own stakeholders.

Every run records its own metadata — when it ran, how long it took, the model used, whether memory and web search were on, and its credit accounting — so a result is reproducible and auditable later.

What you need to bring

Four things, and about 3–6 hours of one person's time.

  • A named owner with the right access

    One person who can work on the agent directly, with about 3–6 hours across the engagement.

  • Agreement to install the Agent Review Center

    It runs in your own environment, so your data stays in your tenant. See install and prerequisites.

  • An agent with a meaningful user base

    In testing, pilot, or production, with enough real traces for the failure modes to be informative.

  • Licensing and credits

    A Copilot Studio license, a Power Apps Premium license, and Copilot credits. See prerequisites.

An agent with little or no real traffic can still be reviewed for configuration and orchestration, but the runtime and conversation analysis will have little to work with.

Start the setup early

The Agent Review Center is installed as part of the Copilot Agent Kit, an open-source toolkit for Copilot Studio agents. It goes into a Power Platform environment in your own tenant.

Start this before your first working session. The tenant admin approvals and the transcript setting are the two things most likely to hold up a review, and neither is quick to arrange on the day.

Data handling

Nothing leaves your tenant.

  • The tool runs in your environment

    The Agent Review Center is installed in your own tenant and runs against your own agents.

  • Your data stays in your tenant

    Transcripts, telemetry, and traces are analyzed where they already live.

  • You control what is shared

    Results are yours. Sharing them outside your team is your decision.

How to get started

Four steps.

  1. Pick the agent or agents you want reviewed

    Something in testing, pilot, or production with a meaningful user base, and enough real traces for the findings to tell you something.

  2. Ask your Microsoft team

    Talk to the Microsoft team you already work with and ask them about the Agent Review Program.

  3. Start the setup early

    Get the prerequisites and permissions in front of your tenant admin, and turn on transcript recording as soon as you can.

  4. Name your owner and book the first slot

    For discovery, Agent Review Center setup, and data preparation.
